Commit and push the repo

Your repository has one commit from 24 Aug. The frontend, seeds, routers, scrapers and translations exist only on your disk. Cloud Run builds from a folder, not from GitHub, so this is not a technical prerequisite, but it is the one step that protects three days of work. Do it first.

05

Create the Postgres instance

You15 min, mostly waiting~₹850/mo, from credit for 90 days

This is the one recurring cost in the whole plan. The smallest tier (db-f1-micro, shared core, 10 GB SSD) holds years of our facts: all seeds, projects, MoUs, finance rows and the proposed-facts queue together are well under 1 GB. Backups run nightly and seven are kept, and point-in-time recovery is on: since the community board went in this database holds writing by members of the public, not only our seeds, so being able to rewind to any minute of the past week matters in a way it did not before. Choose a long password now and keep it in your password manager; you will paste it in step 06 and step 09.

PowerShell
gcloud sql instances create apnn-db `
  --database-version=POSTGRES_16 `
  --tier=db-f1-micro `
  --region=asia-south1 `
  --storage-type=SSD --storage-size=10GB --storage-auto-increase `
  --availability-type=ZONAL `
  --backup-start-time=21:00 --retained-backups-count=7 `
  --enable-point-in-time-recovery

# ~5 to 10 minutes. When it returns:
gcloud sql databases create applatform --instance=apnn-db
gcloud sql users create apnn --instance=apnn-db --password="PASTE-YOUR-LONG-PASSWORD"
Do not add "authorized networks" or open the instance to 0.0.0.0/0. Cloud Run reaches it through a private socket and your PC reaches it through the Auth Proxy (step 09). Neither needs the database exposed to the internet.
Checkgcloud sql instances describe apnn-db --format="value(state)" prints RUNNABLE.
06

Store the secrets

You10 minfree at this volume

Cloud Run must never see passwords in plain environment variables or in the repo. Secret Manager holds them; Cloud Run reads them at start. The database URL uses the Cloud SQL socket path, which is how Cloud Run connects without a public IP.

PowerShell
# 1. database URL (socket form; note the @/ with no host)
$db = "postgresql+asyncpg://apnn:PASTE-YOUR-LONG-PASSWORD@/applatform?host=/cloudsql/ap-nadu-nedu:asia-south1:apnn-db"
[IO.File]::WriteAllText("$env:TEMP\db.txt", $db)
gcloud secrets create DATABASE_URL --data-file="$env:TEMP\db.txt"
Remove-Item "$env:TEMP\db.txt"

# 2. app secret key (random 48 chars)
$key = -join ((48..57 + 65..90 + 97..122) | Get-Random -Count 48 | ForEach-Object {[char]$_})
[IO.File]::WriteAllText("$env:TEMP\key.txt", $key)
gcloud secrets create SECRET_KEY --data-file="$env:TEMP\key.txt"
Remove-Item "$env:TEMP\key.txt"

# 3. moderation key for the community board (sent as the X-Admin-Key header)
$adm = -join ((48..57 + 65..90 + 97..122) | Get-Random -Count 40 | ForEach-Object {[char]$_})
[IO.File]::WriteAllText("$env:TEMP\adm.txt", $adm)
gcloud secrets create ADMIN_KEY --data-file="$env:TEMP\adm.txt"
Write-Host "SAVE THIS IN YOUR PASSWORD MANAGER: $adm"
Remove-Item "$env:TEMP\adm.txt"

# 4. let Cloud Run's default service account read them
$pn = gcloud projects describe ap-nadu-nedu --format="value(projectNumber)"
foreach ($s in "DATABASE_URL","SECRET_KEY","ADMIN_KEY") {
  gcloud secrets add-iam-policy-binding $s `
    --member="serviceAccount:$pn-compute@developer.gserviceaccount.com" `
    --role="roles/secretmanager.secretAccessor"
}

The Anthropic key for the fact pipeline is not needed here: that pipeline runs on your PC, so the key lives in your local backend\.env only.

Checkgcloud secrets list shows all three names. Never print their values into a terminal you might screenshot.
07

Backend prep

Claude, after your go1 sessionfree
What I change, and why each is needed before step 08. These are small, contained edits to the backend; nothing in the frontend or seeds moves. I ship them the usual way and you review before running the deploy.
  • Redis becomes optional. The cache service currently assumes a Redis at localhost. There is no Redis on Cloud Run at this stage, so the app must fall back to an in-process cache and keep serving rather than fail at startup.
  • Cache headers on every read endpoint. Public GET responses get Cache-Control: public, max-age=300, stale-while-revalidate=3600. Firebase Hosting's CDN honours this, which is what lets a lakh of readers hit the edge instead of your database.
  • One uvicorn worker. Cloud Run gives the container one CPU and scales by adding containers; two workers per container only doubles memory. The Dockerfile command changes to --workers 1.
  • Production CORS list from an env var so the web.app origin (and later your domain) is allowed without a code change. With the /api rewrite in step 10 the browser never needs CORS anyway, but the API stays usable directly.
  • Health endpoint reports database reachability so the uptime check in step 11 fails when the DB is down, not only when the container is.
  • Celery import guarded so the API starts with no broker configured. The scheduling code stays in the repo, unused, until we decide whether to retire it.
CheckI verify locally in my sandbox with the same Dockerfile: container starts with no Redis, /health returns 200 with db: ok, and every read endpoint carries the cache header.
08

Deploy the backend to Cloud Run

You10 min, first build is slowfree tier: 2M requests/mo

One command builds the Docker image from your backend folder (Cloud Build does it, you do not need Docker installed), pushes it, and starts the service. The flags are the guard rails: scale to zero when idle, never more than five containers, secrets mounted from Secret Manager, the Cloud SQL socket attached.

PowerShell
cd "C:\Users\gadik\Documents\Claude\Projects\Politics Platform\politics-platform\backend"

gcloud run deploy apnn-api --source . `
  --region asia-south1 --platform managed `
  --allow-unauthenticated `
  --port 8000 --cpu 1 --memory 512Mi --concurrency 80 --timeout 60 `
  --min-instances 0 --max-instances 5 `
  --add-cloudsql-instances ap-nadu-nedu:asia-south1:apnn-db `
  --set-secrets "DATABASE_URL=DATABASE_URL:latest,SECRET_KEY=SECRET_KEY:latest,ADMIN_KEY=ADMIN_KEY:latest" `
  --set-env-vars "^;^APP_ENV=production;ALLOWED_ORIGINS=https://ap-nadu-nedu.web.app,https://apfactcheck.dheeco.com"

# answer Y when asked to create the Artifact Registry repo. 5 to 8 minutes.
# it ends by printing a Service URL like https://apnn-api-xxxxx-el.a.run.app

"Allow unauthenticated" means the public can call the API, which is the point of a public platform; it does not expose the database or the console. The empty database is fine for this step; step 09 fills it.

CheckOpen <Service URL>/health in a browser: JSON with status ok and db: ok. <Service URL>/api/v1/projects returns an empty list, not an error.
09

Migrate and seed from your PC

You15 minfree

The Cloud SQL Auth Proxy is a small program that opens an encrypted tunnel from your PC to the cloud database using your Google login. Through it, the same Alembic migrations and seed loader you run locally run against the cloud. This is also exactly how the scrapers will write to the cloud later (step 12).

Download cloud-sql-proxy.x64.exe from the releases page, rename it to cloud-sql-proxy.exe, and put it in the backend folder. The first command below adds it to .gitignore so the binary never enters the repo.

PowerShell · window 1 (leave running)
cd "C:\Users\gadik\Documents\Claude\Projects\Politics Platform\politics-platform\backend"
Add-Content ..\.gitignore "`ncloud-sql-proxy.exe"
.\cloud-sql-proxy.exe ap-nadu-nedu:asia-south1:apnn-db --port 5435
# port 5435 because your local Postgres already uses 5434
PowerShell · window 2
cd "C:\Users\gadik\Documents\Claude\Projects\Politics Platform\politics-platform\backend"
$env:DATABASE_URL = "postgresql+asyncpg://apnn:PASTE-YOUR-LONG-PASSWORD@127.0.0.1:5435/applatform"

alembic upgrade head            # creates every table in the cloud DB
python scripts\load_seed_data.py   # loads the 7 curated seeds
Setting $env:DATABASE_URL affects only that window. Your local .env and local database are untouched. Close the window when done and the variable is gone.
Check<Service URL>/api/v1/projects now returns your projects, and /api/v1/mous/summits returns the five summits. That is the live database answering from Mumbai.
10

Frontend on Firebase Hosting, with the /api rewrite

You20 minfree tier

Firebase Hosting is Google's static CDN. It serves the React build from edge locations and, through one rule in firebase.json, forwards anything under /api/ to the Cloud Run service. The site and the API therefore share one address, so the frontend calls /api/v1/... relatively and CORS never enters the picture.

The Firebase CLI is a global tool, installed outside the project, so it does not touch node_modules or your dev server.

PowerShell
npm install -g firebase-tools
firebase login

cd "C:\Users\gadik\Documents\Claude\Projects\Politics Platform\politics-platform\ap-nadu-nedu"
firebase init hosting
#  ? Use an existing project  → ap-nadu-nedu
#  ? Public directory          → dist
#  ? Single-page app           → Yes
#  ? Set up GitHub deploys     → No (step 14, later)
#  ? Overwrite dist/index.html → No

Now replace the generated firebase.json with this. The /api/** rule must come before the catch-all, and the long cache on hashed assets is safe because Vite renames files whenever their content changes.

ap-nadu-nedu/firebase.json
{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [
      { "source": "/api/**", "run": { "serviceId": "apnn-api", "region": "asia-south1" } },
      { "source": "**", "destination": "/index.html" }
    ],
    "headers": [
      { "source": "**/*.@(js|css|woff2)",
        "headers": [ { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" } ] },
      { "source": "/index.html",
        "headers": [ { "key": "Cache-Control", "value": "no-cache" } ] }
    ]
  }
}

Create ap-nadu-nedu\.env.production with one line so the production build uses the relative path (your .env keeps pointing at localhost for dev):

ap-nadu-nedu/.env.production
VITE_API_URL=/api/v1
PowerShell
npm run build
firebase deploy --only hosting
# prints: Hosting URL: https://ap-nadu-nedu.web.app
CheckOpen the Hosting URL on your phone over mobile data. Home map loads, Projects shows live data, switching to Telugu translates the page, and the browser's Network tab shows /api/v1/... calls returning from the same host. If you see icons as raw text, the vendored font did not build; tell me.

13

Later: your domain and Cloudflare

You30 min + DNS waitdomain ~₹800 to 1,500/yr

When you own a domain: add the site to Cloudflare (free plan) and point the registrar's nameservers at Cloudflare. In Firebase Hosting → Add custom domain, Google gives you a TXT record and two A records; create them in Cloudflare with the proxy off (grey cloud) until Firebase shows the certificate as active, which can take up to a day. Only then switch the proxy on and set Cloudflare SSL mode to Full (strict). Switching the proxy on too early is the classic way this step fails.

Then add the new origin to the Cloud Run ALLOWED_ORIGINS variable with one gcloud run services update command, which I will give you at that point.

14

Later: auto-deploy from GitHub

Claude, after your gofree

Once you are used to the manual deploy, I replace it with a GitHub Actions workflow: on every push to main, run the backend tests and the i18n parity check, build and deploy the backend to Cloud Run, build and deploy the frontend to Firebase Hosting. Authentication uses Workload Identity Federation, so no service-account key file ever sits in GitHub. From then on, "ship" means "push".
